# 实现说明

这份文档说明 0.8.2 的代码怎么接入 DSH，以及模型选择、滑条和动效分别在哪处理。使用和安装方法见 [README](../README.md)。目前确认过的宿主是 Windows 下的 DSH Web 0.2.1-rc.2。

## 模型按钮怎么接入 DSH

入口通过 `conversation.input.model` slot 注册组件，id 为 `endfield-reasoning-slider/model`，优先级为 `-10`。组件使用 DSH 提供的 React 和 ReactDOM，面板通过 portal 挂到 `document.body`。

读取和保存走的是 DSH 的模型目录接口：

```text
sessionId / slot bindingKey
  → modelDirectories.directoryFor(id)
  → directory.store.getSnapshot() / subscribe()
  → 模型列表、当前模型和档位

用户确认选择
  → directory.select({ provider, model, reasoningEffort? })
  → 宿主返回 ok
  → 更新记忆，播放选中反馈
```

`sessionId` 和 slot 的绑定键分开保留，依次尝试解析目录。由宿主管理模型的子会话不会被强行接管。目录尚未就绪时会重试；绑定成功后仍定期检查目录是否因重连或会话切换而被替换，同时取消旧目录的订阅。

界面用 `useSyncExternalStore` 订阅目录。第一次挂载以及 DSH 在其他入口修改模型后，都以宿主当前值为准。插件没有另外发起推理请求，也没有重写 DSH 的请求流程。

## 档位与记忆

档位直接来自模型的 `reasoning.efforts`，显示顺序跟随宿主。没有推理设置的模型不提供可调滑条；有推理设置但没有声明 `defaultEffort` 时，会增加一个“提供方默认”。选择它时省略 `reasoningEffort`，让宿主决定。

记忆保存在当前站点的 `localStorage`，键名是 `dsh.endfield.reasoning.v1`。每条记录用提供方 id 和模型 id 组成的二元组作键，写入本地存储时最多保留 500 条。同名但属于不同提供方的模型不会混在一起。存储不可用或内容损坏时，界面仍可使用；无法写入的选择会暂存在内存里。

切换模型时，依次尝试该模型记住的档位、同一模型的当前档位、模型默认值，再到提供方默认；每一步都要检查这个档位是否仍在目录里。第一次打开组件不会把浏览器旧记忆写回宿主，而是记录 DSH 正在使用的值。

## 滑条为什么能跟手，又只保存一次

滑条把连续位置 `draft.ratio` 和已保存档位分开处理：

1. 按下轨道时捕获指针，计算 0～1 的位置；移动时只更新本地画面。
2. 松手后用 `round(ratio × (档位数 - 1))` 找最近档位，播放吸附并提交一次。点档位文字也走同一个提交入口。
3. 保存期间保留吸附目标，避免宿主尚未返回时滑块先跳回旧值。重复选择和并发提交会被拦住。
4. 只有 `directory.select()` 返回 `ok` 才更新记忆并播放确认反馈。失败则显示错误，撤掉临时位置，重新显示宿主值。

方向键、`Home`、`End` 和翻页键先预选，松开按键时保存；键盘预选后离开滑条也会提交。`Esc`、指针取消或捕获丢失会取消未提交的手势。如果模型、档位列表或可操作状态在手势中改变，也会取消这次手势，避免把旧目录里的选择写入新目录。

保存超过 15 秒只会提示仍在等待，不会把它当作成功。错误文本在展示前会清理常见 token 和认证参数。

## 面板定位与动效

面板最大宽度为 420px，靠模型按钮对齐，根据上下空间选择展开方向，再限制在视口范围内。定位时会扣除按钮按压、回弹带来的缩放和位移。按钮、面板尺寸或页面滚动变化后会重新计算位置。

面板本体没有开场平移。黑黄覆盖和粒子效果放在独立的 `.dsh-ef-panel-opening` 层里，该层不接收指针事件，也不会推迟内容挂载。容器用 `inset: 0` 限制边界，扩大的 SVG 在容器内裁切，避免制造临时滚动条。这个边界曾导致开场位移，修复经过见 [问题记录](INCIDENTS.md)。

当前开场时序如下，时间从动画开始算起；几个效果会重叠播放：

| 时间 | 效果 |
| --- | --- |
| 0～170ms | 黑黄块从左向右覆盖 |
| 170～210ms | 覆盖保持 |
| 210～500ms | 从左向右粒子化擦除，带像素块和网点 |
| 200～450ms | 覆盖层和粒子同时以 `ease-in-out` 淡出 |
| 155～172ms | 覆盖层黑白反相 |
| 295～312ms | 面板局部像素错位 |
| 530ms | 移除开场动画层 |

覆盖和擦除的运动曲线为 `cubic-bezier(.33, .95, 1, .04)`。两段 17ms 的冲击效果约相当于 60Hz 下的一帧，实际显示帧数取决于设备刷新率和调度。530ms 是动画层清理时间，视觉转场在 500ms 内完成。

关闭时先克隆当前面板，保留滚动位置、计算后的样式和伪元素，再分成高度不一的横条。每条向右匀速拉长，整体在 300ms 内以 `ease-in-out` 从不透明淡到透明。副本中的 id 和 SVG 引用会重新命名；整个画面层设为 `inert`、`aria-hidden`，不能点击或获取焦点。原面板停止交互，动画结束后一起移除。

快速重开会取消上一轮关闭画面；失焦、页面隐藏、关闭时窗口尺寸改变、组件卸载和开启“减少动态效果”也有对应清理。开关动画只控制画面，不提交模型选择。

选中确认是另一组效果：宿主确认成功后，局部黑白闪和震颤持续 165ms，模型弹窗整体震颤持续 146ms，峰值约为横向 1.25px、纵向 0.75px、旋转 0.0875°。它们不靠重新挂载面板来重播。

## 输入框装饰和发送反馈

入口识别包含 `[data-composer-input]` 的 `[data-composer-card]`，排除工作区入口卡片，再挂载侧带、刻线、挂孔、等高线、角标和工具栏装饰。文字编辑和发送仍由 DSH 处理。`MutationObserver` 跟踪输入框重建，卸载时移除装饰、标记、监听器和动画。

这里仍有宿主版本依赖：工具栏按 class 中的 `_row` 识别，主按钮按 `_primary` 识别，再加上插件自己的 `data-ef-*` 标记。升级 DSH 后如果输入框装饰或发送反馈失效，应先核对这些结构。

点击可用的发送按钮会立即播放 165ms 黑白闪和黄色短条跳动。快捷键则先观察宿主是否进入本地提交状态或清空编辑器，再播放相同反馈；不用等待模型回复。停止按钮、换行、输入法组合输入和候选项选择会被排除，插件不调用额外的发送处理器。

CSS 和脚本都跟随 `prefers-reduced-motion`。开启“减少动态效果”后，面板直接显示或关闭，按钮、选中和发送动画也会停止。

## 构建、安装和检查

[build.mjs](../scripts/build.mjs) 按固定顺序拼接源码，把 CSS 和 Saira 字体内联到 `lib/client.js`，通过 DSH 的 `__ModuleLoader__` 加载。修改应落在 `src/`，再构建产物。

[install-profile.mjs](../scripts/install-profile.mjs) 默认操作当前用户的 Web profile，也接受显式的 profile 路径。它会检查 profile 和已有目录链接，备份配置，再加入插件依赖与 bundle 配置；Windows 下通过目录联接加载插件。卸载只移除核实属于本插件的条目和链接，安装失败时尝试回滚。本项目没有验证 Desktop 专用 profile。

默认的 `npm test` 覆盖核心逻辑和临时 profile 安装、卸载。浏览器动效、真实宿主契约和集成检查另有脚本；它们需要各自的环境，不能用默认测试通过来代替。具体命令见 [README 的开发部分](../README.md#开发)，历史验证范围见 [VALIDATION.md](../VALIDATION.md)。
